# FQPlanner 大脑侧 · 完整交接文档(接待 Demo)

> 面向接手人:看完这一份,能独立把大脑跑起来、理解接待怎么从"一句话"变成机器人一步步动作、知道跟外部三个组(世界模型/导航/VLA)怎么对接、工作点怎么算出来。
> 细节分散在 `docs/对接手册-*.md`、各模块代码注释、`nx_voice/README.md`,本文是**总纲 + 索引**。

---

## 0. 一句话

**大脑 = 把自然语言/语音指令,经 LLM 规划 + 技能(skill) + 双记忆,变成机器人一步步动作。** 接待 Demo 的完整故事:
> 会议前 → 开灯 → 扫描会议室/茶水间 → 按参会人数数可乐缺口 → 去茶水间一罐一罐补 → 摆到会议桌 → 复核 → 语音播报 → 事后反思生成新 SOP。

**核心范式:大脑只出"语义 + 坐标",不越界**——抓/放怎么做交给 VLA 组、怎么走交给导航组、认物体/建图交给世界模型组。

## 1. 整体架构

```
                        ┌─────────────────────── 大脑(这个仓库) ───────────────────────┐
   语音"开始接待"         │                                                              │
   (NX 上 M260 麦)  ──POST──►  deploy (8888, Web 控制台/前端)                            │
   nx_voice/            │            │  转发                                            │
                        │            ▼                                                 │
   前端"一键接待" ───────►   master (5000, LLM 任务规划) ──识别接待──► 接待 skill(自带SOP+经验)│
                        │            │                         reception_loop 闭环      │
                        │            ▼ MCP 工具调用                                      │
                        │       slaver (工具执行) ◄──► Redis (6379, 消息总线)            │
                        └────────────┬──────────────┬───────────────┬─────────────────┘
                                     │语义+坐标      │坐标            │语义
                                     ▼              ▼               ▼
                          世界模型组 PBD      导航组 G1control      VLA 组
                          (语义地图/占据)     (建图/定位/规划/避障)  (抓/放/看图)
                          pbd_world.py        HTTP↔ROS2 桥          HTTP /grasp /place
```

**大脑三进程 + Redis**(都在本机/大脑机):

| 进程 | 端口 | 角色 | 入口 |
|---|---|---|---|
| **master** | 5000 | LLM 任务规划:识别任务 → 拆子任务 / 命中 skill | `master/run.py` |
| **slaver** | — | MCP 工具执行:真正调原语(walk/pick/place…) | `slaver/run.py` |
| **deploy** | 8888 | Web 控制台/前端:发任务、看进度、看报告 | `deploy/run.py` |
| **Redis** | 6379 | master↔slaver 消息总线 | `redis-server` |

**外部三个组**(不在本仓库,靠 HTTP/ROS2 对接,见 §4):
- **世界模型组 PBD**:语义地图(数物体、给位姿、占据图)——大脑侧适配 `master/sop/pbd_world.py`。
- **导航组 G1control**:建图/定位/路径规划/避障/行走(ROS2)。
- **VLA 组**:抓取/放置/看图(HTTP)。

## 2. 怎么起(启动顺序)

> 详见 `usage.md` 和 `README.md`。两个 conda 环境:`robocasa`(仿真) + `FQPlanner`(规划链路)。

```bash
# 1. Redis(消息总线)
redis-server

# 2. 仿真后端(接真机时可跳过/换 robot_api)——MuJoCo (5001)
conda activate robocasa
cd serve && python main.py            # 加 --no-viewer 只起 API 不开窗

#    (可选) ACT 抓取推理服务 (5003)
conda activate FQPlanner
python services/act_server.py --policy-path <ckpt> --port 5003

# 3~5. 规划链路(大脑三件套)
conda activate FQPlanner
python master/run.py                  # 🧠 5000  任务规划
python slaver/run.py                  # 🛠️ 工具执行
python deploy/run.py                  # 🖥️ 8888  Web 控制台
```

- **Web UI**:http://127.0.0.1:8888
- **改配置后重启**:`robot_api/config.yaml` 是后端总闸(mock/真机切换);改了要**重启 master + slaver**(RobotRuntime 是单例、缓存在内存)。
- **注意**:起服务用 `FQPlanner` conda 环境;别的环境可能缺 `dotenv`/`redis` 等依赖。

## 3. 接待:一句话 → 一步步动作(核心流程)

### 3.1 触发的两种方式
- **前端**:控制台点"会议接待"(或输入框打"开始接待")→ `POST deploy:8888/publish_task {"task":"开始接待"}`。
- **语音**:对 NX 上的 M260 麦说"开始接待" → NX 脚本识别 → 同一个 `POST`(见 §6)。

### 3.2 master 收到后
`master/agents/agent.py` 的 `publish_global_task`:
1. `_is_reception_task("开始接待")` 命中接待关键词 → **不走通用 LLM 拆解**,直接 `_run_reception_skill`(和"整理桌面"走专门分支同一路子)。
2. 起一个后台线程跑 **接待 skill**;`_reception_running` 做互斥——**上一次没跑完,重复触发直接忽略**(防连发/防两个线程打架)。
3. 每个子任务通过 `on_step` 回调写进 `task_status` → 前端复用显示(🧠思考 + 子任务 ✓)。

### 3.3 接待 skill = 自带 SOP + 经验的高层技能
`master/sop/reception_skill.py` → 调 `reception_loop.run_reception`(闭环执行体)。三样知识:
- **执行体**:`reception_loop.py` 的补货闭环(内部调 walk/pick/place 原语,backend 可切真机)。
- **SOP**:`reception_sop.yaml`(标准流程 + `learned_rules`;事后反思会 update 出 `reception_sop_v2.yaml`)。
- **经验**:`global_memory.json`(成功规则 + 失败模型 empty_grasp/false_success…)。

### 3.4 reception_loop 闭环的一步步(`master/sop/reception_loop.py` `run_reception`)
```
① reset_world(重置本次虚拟环境:可乐数/灯态)         ← 每次接待都是干净环境
   retrieve 人类示范经验(demonstration,§7)         ← re-ground 到本次
② 开灯
③ 扫描会议室/茶水间(数饮料 / 认障碍)
④ 按参会人数算可乐缺口
⑤ 一罐一罐补货:walk → pick → walk → place
     每步【重新观测做状态确认】(不采信 VLA/导航自报);失败按【观测到的现状】智能恢复
⑥ 复核前后状态(数量 / 灯 / 摆放)
⑦ 语音播报 + 结构化完成报告(report card,前端展示)
⑧ 事后反思 → 生成新版 SOP(reception_sop_v2.yaml) + trace 存档
```

**关键设计**:每步都**重新观测确认**(手上有没有可乐、人在哪、灯开没),不信技能自报——"自报成功 ≠ 真成功"(§4 VLA 约定同源)。

## 4. 三个对接(大脑 ↔ 外部组)

> **总原则**:大脑对 **VLA 给语义**(物体名/区域名,不给坐标)、对 **导航/PBD 给坐标**(从场景图算好的 map 系 x,y,yaw)。各组的详细接口见对应手册。

### 4.1 世界模型组 PBD(语义地图) —— `docs/对接手册-导航建图组.md`
- **拉**:占据地图 / 机器人位姿 / 语义物体(类别+中心+bbox+父子+稳定 id) / RGB(按需)。
- **回**:任务上下文 / **工作点导航目标**(map 系坐标)。
- 大脑侧适配:`master/sop/pbd_world.py`(纯 Python 客户端 HTTP 轮询;PBD 主机跑重服务)。轮询 = 大脑主动 GET 拉最新。
- 客户端包 + 文档:`PBD_AG_大脑端轻量客户端_v0.1.0/`(`.whl` 二进制不在库,单独发)。
- **注意**:大脑算工作点**坐标**发 PBD(导航用),给 VLA 的是**语义**——两者别混。

### 4.2 导航组 G1control —— `docs/对接手册-导航组-接待demo.md`
- 导航栈:Cartographer 建图 + Dijkstra 规划 + nav2point 避障 + SONIC 行走(纯 ROS2)。
- 大脑侧起 **HTTP↔ROS2 桥**(`docker/nav2/.../g1_nav_bridge.py`)翻译:
  - `/g1pilot/goal`(PoseStamped, map 系):桥把大脑算的目标点坐标发进去;
  - `/lidar_odometry/pose_fixed`(Odometry):桥读位姿判到达;
  - `/map`(OccupancyGrid):2D 占据。
- **大脑给坐标**(map 系 x,y,yaw),导航**不维护"地名→坐标"表**;"数可乐/认椅子"的语义**不归导航**(归世界模型组/VLA)。
- office 地图坐标系与大脑 3DGS **极可能同源**(X 起点≈−7、Y≈±6),同源则导航用他们地图、渲染用我们 3DGS、位姿通用。

### 4.3 VLA 组(抓/放) —— `docs/对接手册-VLA组-接待demo.md`
- VLA 起 HTTP 服务:`POST /grasp {object_name}`、`POST /place {object_name,target}`、`POST /screenshot`、`GET /objects`(带 `grasped`)或 `GET /gripper_status`。
- **大脑给语义不给坐标**(可乐 / meeting_room),抓哪怎么抓 VLA 看图解决;抓/放前机器人已由导航送到位。
- **三条约定**:① 给语义不给坐标;② **自报成功 ≠ 真成功**(大脑抓完查 `grasped`、放完拍照/数物体确认,空抓必须报 false);③ 抓不到报 `{success:false}`,大脑重试 ≤2 次、超限停下上报。
- pi0.5 还在训,可先用早期 checkpoint/脚本抓取兜底,端口就绪一行切过去。

## 5. 工作点怎么生成(大脑侧算导航目标)

> 目标:接待要**每个操作目标(可乐/每把椅子)都有一个能站得住、朝向对的工作点**,发给导航/PBD。

```
① free_points(可通行点)     nav2/free_points_generator.py
     从占据栅格地图采样,clearance≥0.35 过滤掉贴墙/障碍的点
② 接待版工作点(每目标一个)  master/sop/reception_workpoints.py  gen_reception_workpoints()
     · 可乐/冰箱  → 前面选一个 free_point,yaw 朝可乐(取)
     · 每把椅子    → 旁边选一个 free_point,yaw 朝【桌子】(把可乐放到该座位前的桌面)
     · 距离窗 [0.3, 0.6]m(可操作范围);够不到的目标 → 上报"unreachable"
③ 发给 PBD/导航     算好的 (x, y, yaw) map 系坐标 → §4.1/§4.2
```

- 和通用的 `nav2/workpoints_generator.py`(贪心最少覆盖)不同:**接待不合并**,每个目标都要能操作到。
- 数据源:真实来自 PBD 语义地图(`pbd_world` 拉桌/椅/可乐中心 + 占据图 → free_points);PBD 离线时 `python master/sop/reception_workpoints.py --demo` 用假数据验证选点/朝向逻辑。

## 6. 语音触发(NX 侧) —— 详见 `nx_voice/README.md`

```
M260 USB 麦 → arecord 录音 → 音量门限(VAD)滤静音 → qwen-omni 云 ASR 转文字
→ 含"开始接待" → POST 大脑 deploy /publish_task → §3
```
- 脚本 `nx_voice/reception_voice.py` 常驻跑在 NX(Jetson);key 从 `~/.vlm_key` 读(不入库)。
- **为什么不用 G1 板载麦**:探尽了——板载麦音频输出没启用、ALSA 无设备、SDK 的 ASR 只注册没实现、要动锁死的核心主机/MCU 固件。所以外接 M260。详见 `nx_voice/README.md` 文末。

## 7. 记忆 + 人类示教(让大脑越做越会)

**双记忆(HarnessVLA 路子)**,都在 `master/sop/reception_memory/`:
- **Global Memory**(`global_memory.json`):跨任务通用规则 + 失败模型(empty_grasp/false_success)。接待 skill 每次读、用。
- **Task Specific Memory**(`demonstration_*.json`):某次示范的具体实例/特情("可乐在茶水间冰箱""取第二罐前等他人取物")。接待开头 `retrieve_demonstration()` 读出来 re-ground 到本次(前端显示"📖 参考人类示范经验")。

**人类示教更新 SOP**(换任务不改代码):
```
上传示范视频(/teach 页) → video_to_actions.py(cv2 抽帧 + qwen-vl → 动作序列)
→ learn_from_demo.py(deepseek 提炼,反幻觉,分两层) → persist 落盘:
      Global → global_memory.json + SOP learned_rules
      Task Specific → demonstration_*.json  ──(§3.4 ①)──► 接待 retrieve 用上
```
- 全程**读文件、不写死**:换示范视频 → 写新 demonstration → 接待自动读到新的,零改代码。

## 8. 状态确认 + 反思(可靠性的来龙去脉)

- **每步重新观测**:接待每个子任务后,用观测(mock 读虚拟世界 / 真机读相机+VLM)确认真实状态,不采信技能自报。观测源 `reception_skills.obs_*` 统一(mock/robot_api 切换)。
- **VLM-critic**:用 qwen3-vl-plus(temperature 0)看图判成败(从七月桌面 demo 迁移过来)。
- **事后反思**:一次接待的 trace → 反思 → 生成新版 SOP(`reception_sop_v2.yaml`),下次更聪明。
