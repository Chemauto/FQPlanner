# FQPlanner 大脑 ↔ 导航建图组 对接文档

**一句话:你们给「地图 + 场景图 + 机器人位置」,并执行大脑发的坐标导航任务。名字怎么变成坐标、机器人该站哪,大脑自己算,你们不用管。**

(比上一版的变化:不再需要你们维护「区域名 → 坐标」表,导航任务只收坐标。)

## 1. 分工

```
你们:  建 2D 地图 + 场景关系图 + 报机器人位置 + 执行坐标导航(Nav2)
大脑:  决定去哪、去干什么(目标点由大脑根据你们的地图和场景图算出来)
VLA组: 到点之后的抓取/放置(另一份文档)
```

## 2. 通道:HTTP,你们起两个服务(都几乎零代码)

把两个服务的 `IP:端口` 发毕艺恒即可联调:

**① 数据服务——给大脑拉文件。**
在你们的导出目录跑一个静态文件服务就行,一条命令:

```bash
cd <你们的导出目录> && python3 -m http.server 8000
```

大脑会来 GET 这四个文件(格式都是你们现有的,不用改):

| 文件 | 是什么 |
|---|---|
| `map.yaml` + `map.pgm` | 2D 占据地图 |
| `total_scene_graph_latest.json` | 场景关系图(哪张桌子在哪、桌上有什么) |
| `nav_map_latest.json` | `robot_xyt` = 机器人当前位置 [x, y, yaw] |

每次更新带 revision / sha256(你们现有机制),对不上大脑不执行。

**② 导航服务——收大脑的目标点。**
直接跑我们仓库现成的 ROS2 节点,不用写代码:

```bash
# 仓库路径: docker/nav2/ros2_ws/src/fqplanner_nav_bridge/fqplanner_nav_bridge/nav2_goal_bridge.py
ros2 run fqplanner_nav_bridge nav2_goal_bridge \
  --ros-args -p http_host:=0.0.0.0 -p http_port:=5102 -p verify_final_pose:=false
```

- 接口:`POST /nav {x, y, target_yaw}`(map 系、米;yaw 给度或弧度都认)。
- **同步执行**:它把目标转成 NavigateToPose 交给你们的 Nav2,走完才返回 `{success: true/false, ...}`。
- `verify_final_pose:=false` 必须带(默认的成功校验是仿真专用)。
- 不想用我们的节点、自己实现同样的 `POST /nav` 也行,行为一致即可。

以后要按你们 README 说的升级成 ROS Topic/Action 也没问题,先用 HTTP 跑通。

## 3. 两条约定

- 所有坐标都在 **map 系**,单位米,yaw 逆时针。你们首次交接包我们已核对过,双方换算一致,**保持现状即可**。
- 重新建图(换 odom 会话)时发新 revision,大脑收到会自动重算目标点。

## 4. 三个问题:建议做法 + 谁动手

| # | 问题 | 建议做法 | 谁改 | 做不到的兜底 |
|---|---|---|---|---|
| ① | 机器人位置能持续刷新吗? | 导航期间约每秒把 `robot_xyt` 覆写进 `nav_map_latest.json`(先写临时文件再改名,防止读到半截) | **你们**,小改 | 大脑改用导航返回结果兜底,只是过程中看不到机器人在哪 |
| ② | 物体编号能保持稳定吗?(`cola_can_1` 下版还叫这个名) | 编号只增不复用:新物体往后排,消失的编号不再用;或每版附一张新旧编号对照表 | **你们**,改编号分配逻辑 | 我们按"类别+位置最近"自己匹配(我们写),但同类物体多时会认错 |
| ③ | 正式场景把地图扫全 | 任务会经过的区域完整扫一遍再导出。首包偏稀(起点离障碍仅 0.11 m),我们选站位要求 ≥0.25 m,图太稀选不出点 | **你们**,纯操作不改代码 | 我们放宽站位标准(改一行配置),导航时靠你们的实时避障兜底 |

## 5. 联调三步

1. **离线验收 ✅ 已完成**——你们的首次交接包(地图、场景图、格式)大脑侧已全部解析通过,HTTP 通道也已在大脑侧模拟自测通过。
2. **单点导航**:你们起两个服务、发来 IP:端口 → 大脑 GET 四个文件 + POST 一个真实目标点 → 返回 success。
3. **全链任务**:大脑下一个完整任务(导航→抓取→导航→放置),导航部分走你们,抓放走 VLA 组。
